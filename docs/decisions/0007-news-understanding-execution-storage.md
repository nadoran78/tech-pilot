# 0007: 뉴스 설명·분류의 최소 실행 및 저장 방식

- **Status:** Accepted
- **Date:** 2026-10-17
- **Phase:** 4
- **Purpose:** 첫 처리 경로와 실행·저장 방식의 선택지 및 승인 순서를 제안한다.
- **Read when:** 제목 기반 처리·모델 도입·생성 결과 저장의 승인 여부를 검토할 때
- **Related documents:** [4단계](../phases/04-news-understanding.md), [입력·출력 계약](../specs/news-understanding-input-output.md), [평가 기준](../specs/news-understanding-evaluation.md), [저장·재실행 계약](../specs/news-understanding-storage.md), [기술 기준](../architecture/tech-stack.md)

## Context

Issue #65에서 develop `7270238`의 입력·평가 제안과 기존 SQLite 기술 기준을 대조했다. 당시 입력·평가안은 Draft였고 이 ADR도 Proposed였다. 2026-10-18 사용자가 입력·출력안, 평가 기준, 이 ADR의 실행·저장·재실행안을 모두 명시적으로 승인했으므로 Issue #67에서 Accepted로 전환한다. 승인과 품질 평가 통과는 별개다. 현재 메타데이터만으로 원문 내용 요약을 뒷받침할 수 없다는 한계는 유지한다.

## Options Considered

아래는 구조적 장단점 비교이며 실측 품질·속도·가격이나 특정 공급자 제품 추천이 아니다. 구체적 모델·실행기 선정은 별도 근거가 필요하다.

| 선택지 | 품질 검증 가능성 | 운영 부담·비용 | 외부 전송 | 현재 제안 |
|---|---|---|---|---|
| 명시적 규칙·고정 형식 | 근거 표현과 보류를 합성 사례로 재현하기 쉬움. 키워드 충돌·다국어·문맥 한계, 의미 이해 품질 보장 불가 | 모델 설치·추론 호출 없이 가능하나 규칙 작성·유지 비용 존재 | 네트워크 없는 구현으로 제한 가능 | 첫 비교 기준선 후보 |
| 로컬 모델 | 문맥 대응을 실험할 수 있지만 동일 평가와 환각 검토 필요; 우수성 미입증 | 장치 자원·모델 확보·라이선스·실행기 관리 검토 필요, 무료 운영 단정 금지 | 로컬 추론만으로 전체 실행기의 통신 차단이 보장되지는 않음 | 필요성이 확인되면 별도 선택·검증 |
| 외부 모델 | 동일 표본 비교 가능하지만 출력 변동·입력 밖 추론 검토 필요; 우수성 미입증 | 공급자·가격·상한·오류·사용량·비밀 값 관리 결정 필요 | 입력 전송·보존 조건 별도 검토와 승인 필요 | 현재 호출·공급자 선정 보류 |

입력을 늘려 본문 요약부터 하는 대안은 별도 접근·보관 조건과 평가 근거를 요구한다. 이 결정안은 해당 경로를 금지하거나 기각하지 않지만 첫 구현에 자동 포함하지 않는다.

## Decision — 승인된 기준

1. **입력 경로:** 이미 저장된 제목과 연결 메타데이터로 제목 기반 설명·잠정 분류부터 작게 시작한다. 원문 요약 요청은 `insufficient_information`으로 처리한다. 제목을 다시 설명한 텍스트를 `summarized`로 표시하지 않는다.
2. **실행 기준선 권장안:** 승인 후 첫 비교 기준선은 수동·네트워크 없는 명시적 규칙과 고정 형식으로 제안한다. 명백한 근거가 없거나 규칙이 충돌하면 판단 불가로 남긴다. 규칙 목록·표시 문구는 구현 전 검토하며 높은 분류 성능을 약속하지 않는다. 생성형 모델을 대체하는 최종 선택이 아니다.
3. **저장:** 기존 SQLite와 명시적 migration 경계를 재사용하되 원본 뉴스·수집 이력과 분리한 생성 결과/시도 기록을 둔다. 구체적 table·schema·migration은 Issue #67에서 구현한다. 논리 계약과 구현 연결은 [저장·재실행 계약](../specs/news-understanding-storage.md)이 기준이다.
4. **부작용 제한:** 원본 필드를 수정하거나 URL을 열지 않는다. 추가 수집·원문·API·모델 설치/실행·외부 전송·자동화는 이번 문서 작업과 첫 기준선 제안에 포함하지 않는다.

## 승인 항목과 선후 관계

| 승인 묶음 | 사용자 확인이 필요한 내용 | 현재 상태 |
|---|---|---|
| 입력·출력 | 제목 기반 경로, 설명/원문 요약 구분·보류 상태·분류 범주 | 2026-10-18 Accepted |
| 평가 | 12개 구성안·분류 10/12 출발점·중대 오류 0건·사람 검토 방식 | 2026-10-18 Accepted, 실제 평가 미실행 |
| 기술·저장 | 규칙 기준선, SQLite 분리 저장·재실행 논리 계약과 검증 범위 | 2026-10-18 Accepted |

이번 승인으로 세 묶음의 합의를 확인했다. Issue #67은 합성 입력·가짜 처리기로 저장 기반부터 구현하며 구체적 규칙·수동 진입점·실제 표본 평가는 후속 이슈다. 외부 모델을 추후 선택하면 전송 조건·비용 상한·호출 승인을 별도로 받는다. 문서 PR 병합은 사용자 승인을 대체하지 않는다.

## Consequences and Next Work

- 장점: 모델 없이 입력 검증·보류·근거 연결·저장·재실행의 작은 경로를 검증할 수 있고, 추후 모델 비교의 기준선이 생긴다.
- 한계: 제목 설명은 실질적 정보 이득이 적을 수 있고 규칙 분류는 쉽게 일반화되지 않는다. 판단 불가가 많거나 읽기 유용성이 낮으면 입력/방법을 재검토한다. 모델 도입만으로 입력 부족이 해결되는 것도 아니다.
- 승인 후 첫 구현 이슈: 합성 입력과 가짜 처리기로 원본 참조·상태·결과 검증, 임시 DB 저장·재실행 계약부터 검증한다. 규칙·수동 진입점·표본 평가는 별도 작은 이슈로 분리 가능하다. 운영 DB migration·실제 평가·구체적 규칙은 이 문서 작성으로 실행하지 않는다.
- 모델·비용·비밀 값·개인 영향·의미 통합·블로그는 후속 범위다. 보존 기간·명시적 정리·운영 관측은 자동화 전 재검토하며 자동 삭제는 도입하지 않는 방향을 제안한다.

최초 결정안은 모델 설치·API 호출·벤치마크 없이 문서와 수작업 사례로 점검했다. Accepted는 사용자 결정 기록이며 실행 품질·성능·비용 수치는 여전히 미측정이다.
