# Product Roadmap

- **Status:** Accepted
- **Applies to:** All phases
- **Purpose:** 프로젝트의 단계별 발전 순서와 전환 원칙을 정의한다.
- **Read when:** 현재 범위, 다음 단계 또는 기능의 도입 시점을 판단할 때
- **Related documents:** [문서 인덱스](../INDEX.md), [제품 비전](vision.md)

## Phases

### 1. 프로젝트 문서 골격 구성 — Active

제품 목표, 단계, 문서 연결 방식과 작업 원칙을 정리해 사람과 Codex가 같은 맥락에서 작업할 수 있게 한다.

상세 범위: [1단계 문서](../phases/01-project-foundation.md)

### 2. 기술 스택 선정 — Draft

뉴스 수집 MVP에 필요한 언어, 실행 형태, 저장 방식, 수집 방식, 테스트와 운영 기반을 비교하고 결정한다.

상세 범위: [2단계 문서](../phases/02-tech-stack-selection.md)

### 3. AI 기술 뉴스 수집 및 보관 — Draft

새 AI 기술 발표를 신뢰할 수 있는 출처에서 발견하고, 원본 근거와 함께 반복 가능한 형태로 축적한다. 동일 URL이나 콘텐츠의 기술적 중복 방지도 이 단계에 포함한다.

상세 범위: [3단계 문서](../phases/03-news-collection.md)

### 4. 요약·분류 및 의미 기반 통합 — Planned

수집한 항목을 이해하기 쉽게 요약·분류하고, 서로 다른 기사와 하나의 공식 발표처럼 의미상 같은 사건을 연결한다.

#### Planned output extension: Obsidian/Quartz blog

뉴스 품질을 검토한 뒤, 품질이 검증된 뉴스를 Obsidian 호환 Markdown 블로그 글로 작성하고 이미 구성된 Quartz 블로그의 콘텐츠 디렉터리로 복사하는 기능을 선택적으로 추가한다.

Tech Pilot의 책임은 블로그 초안 작성과 지정된 경로로의 복사까지다. 기존 Quartz 블로그의 구성, 빌드와 배포는 이 프로젝트의 책임 범위에 포함하지 않는다. 상세 포맷과 연동 계약은 이 기능을 활성화할 때 별도 문서로 정의한다.

### 5. 개인 연관성 분석 — Planned

사용자의 프로젝트, 기술 스택, 학습 상태와 목표를 구조화하고 기술 변화가 미치는 영향을 분석한다.

### 6. 학습·도입 우선순위 추천 — Planned

기대 효과, 비용, 성숙도와 위험을 비교해 학습, 실험, 적용, 관찰 또는 무시 중 다음 행동을 추천한다.

### 7. 실험형 개인 AI CTO — Planned

작은 PoC, 벤치마크와 구현 계획을 통해 추천의 가치를 검증하고, 사용자 승인 아래 실제 프로젝트 변화를 지원한다.

## Phase Transition Rules

- 현재 단계의 완료 조건을 먼저 검토한다.
- 남은 문제가 다음 단계의 진행을 방해하는지 구분한다.
- 사용자가 전환을 명시적으로 결정하면 현재 단계와 인덱스의 상태를 함께 갱신한다.
- 다음 단계가 활성화될 때만 필요한 상세 설계 문서를 만든다.
- 후속 확장을 고려할 수는 있지만, 현재 단계 밖의 기능을 미리 구현하지 않는다.

로드맵은 방향을 고정하기 위한 족쇄가 아니다. 학습 결과로 순서를 바꿔야 한다면 변경 이유와 영향을 기록하고 사용자와 합의한 뒤 갱신한다.
