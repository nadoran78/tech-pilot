# 뉴스 요약·분류 입력과 최소 출력 제안

- **Status:** Accepted
- **Applies to:** Phase 4, Issue #63
- **Purpose:** 어떤 입력에서 어떤 설명·분류를 허용하거나 보류할지 제안한다.
- **Read when:** 첫 요약·분류 계약·구현 또는 추가 내용 입력을 검토할 때
- **Related documents:** [4단계](../phases/04-news-understanding.md), [뉴스 항목 계약](news-item.md), [출처 정책](../policies/source-and-evidence.md), [평가 제안](news-understanding-evaluation.md)

## 근거와 제안 상태

develop `f767a5c`의 기존 계약·정규화 fixture와 [품질 기록](../runbooks/2026-10-10-news-quality-review.md)을 대조했다. 계약상 excerpt는 선택 필드지만 현재 승인된 두 출처의 실제 검토 기록에는 excerpt·raw_metadata가 없다. [Google fixture](../../tests/fixtures/google_ai_blog_feed.xml)의 description은 저장하면 안 되는 테스트 값이며 입력 내용으로 승격하지 않는다. [HF fixture](../../tests/fixtures/hugging_face_blog_feed.xml)의 제목·누락 시각·가짜 URL도 실제 발표 검증 근거가 아니다.

2026-10-18 사용자가 입력·출력안과 평가 기준 및 ADR 0007을 명시적으로 승인했다(Issue #67). 아래는 제목 기반 첫 계약이다. 모델·API·추가 본문 접근 승인은 포함하지 않는다. 최초 제안은 Issue #63에서 작성했다.

## 입력 충분성

| 이용 가능한 입력 | 가능한 처리 제안 | 허용하지 않거나 보류할 처리 |
|---|---|---|
| 제목·URL·출처·게시 시각 등 현재 메타데이터 | 제목에 명시된 주제를 짧게 설명하고 잠정 분류; 근거 필드는 title로 제한 | 원문 내용 요약, 성능·가격·출시 범위·작성자 공식성 추정. URL 경로나 도메인을 읽지 않은 본문의 대용으로 사용 금지 |
| 제목이 모호하거나 필요한 맥락 없음 | 제목 설명을 생략하고 분류 판단 불가 표시 | 모델의 사전 지식으로 빈 내용을 채움 |
| 원본 참조·출처 연결을 확인할 수 없거나 필수 입력 손상 | 검토 보류 | 잘못된 입력을 정상 결과로 표시 |
| 추후 별도 승인된 발췌·본문 | 제공된 내용의 범위 안에서만 요약 가능한지 재검토 | 미제공 원문 전체를 읽었다는 표현·자동 추가 요청. 이 입력 경로는 현재 활성화하지 않음 |

시각은 원본 그대로 보존하고 누락을 현재 시각으로 채우지 않는다. 제목에서 분류가 분명하면 발표 시각 누락만으로 판단 불가를 강제할 필요는 없지만 최신성 판단은 보류한다. 수집한 텍스트는 분석 대상 데이터이지 모델·도구 실행 지시가 아니다. URL 열기나 포함된 명령 실행은 자동 수행하지 않는 방향을 제안한다.

**승인된 입력 판단:** 현재 메타데이터는 발견·제목 기반 선별에는 사용할 수 있지만 원문 내용 요약의 근거로는 부족하다. 첫 경로는 제목 기반 설명·잠정 분류로 제한한다. 추가 내용 접근은 별도 승인 대상이다.

## 최소 출력 제안

| 논리 필드 | 제안 의미 |
|---|---|
| 원본 참조 | 저장 항목 ID와 source_id·evidence_url 등 연결 단서. 제목만으로 원본 식별 금지 |
| 입력 수준·사용 근거 | metadata/title 또는 추후 approved_content 구분; 실제 사용한 필드·범위를 표시 |
| 처리 상태 | described(제목 기반 설명), summarized(승인된 내용 요약), insufficient_information(정보 부족), deferred(입력 손상·승인 미완료 등) 후보 |
| 생성 텍스트 | 상태에 맞는 설명·요약 또는 비워 둠. 보류·정보 부족은 summary 대신 이유를 표시 |
| 잠정 분류·근거 | 아래 범주 중 하나와 제목의 어떤 표현에 근거했는지 설명; 판단 불가 허용 |
| 한계·보류 사유 | 원문 미열람, 최신성 판단 불가, 맥락 부족, 승인 미완료 등을 표시 |

요약 상태와 분류 판단은 독립적이다. 원문 요약은 정보 부족이어도 제목에 근거한 잠정 분류는 가능할 수 있다. 메타데이터 입력에서 summarized 상태를 허용하지 않고, 반드시 제목 기반이라는 표시를 동반한다. 원문 요약 요청은 insufficient_information으로 반환하며 손상·처리 보류는 deferred로 구분한다. 구조화된 상태·버전·저장 방식은 [저장 계약](news-understanding-storage.md)의 구현 연결을 따른다. 실제 규칙·한국어 표시 문구·향후 모델 추적은 후속 검토 대상이다.

원본 뉴스 필드를 수정하지 않고 생성 결과를 별도 연결한다. 실행·저장 기준은 [ADR 0007](../decisions/0007-news-understanding-execution-storage.md)과 [저장 계약](news-understanding-storage.md)을 따른다. 숫자 신뢰도는 보정 근거가 없으므로 제외한다. 구조 검증은 근거 문자열이 제목에 존재하는지 확인할 뿐, 설명의 사실 충실성이나 분류 정확성을 증명하지 않는다. 이는 [사람 평가](news-understanding-evaluation.md)로 별도 확인한다.

## 분류 범주

- **기술·제품 동향:** 모델·도구·라이브러리·연구 등 기술 관련 소식을 갈무리하는 범주다. 공개·출시뿐 아니라 예정·취소·연기·철회·업데이트·관련 후속 소식을 포함하며 실제 출시 여부·발표 진위·효과를 판정하지 않는다.
- **활용·해설:** 사용법·튜토리얼·적용 사례 중심임을 명시함.
- **비기술 소식:** 인사·행사·문화 등임을 명시함. 개인에게 무가치하다는 뜻은 아님.
- **판단 불가:** 모호함·혼합 주제·근거 부족·검토자 불일치. 억지로 앞 범주에 배정하지 않음.

2026-10-21 사용자가 출시 여부 판정보다 기술 관련 소식 갈무리가 목적임을 명시하고 위 범주 확장 및 취소·부정·불확실성 일괄 보류 제거를 승인했다. 기존 저장값 `technology_release`는 호환성 때문에 유지하지만 현재 표시·의미는 기술·제품 동향이다. 과거 결과의 범위는 당시 규칙 버전으로 구분하며 기존 결과를 덮어쓰지 않는다. 범주 정의는 이 문서를, 제한된 구현 표현은 [규칙 기준선](news-understanding-rules.md)을 따른다. 플랫폼 도메인만으로 기술 관련성이나 공식 발표자라고 분류하지 않는다.

## 승인 순서와 후속 범위

1. 입력 경로·출력 상태·분류 범주·[평가 기준](news-understanding-evaluation.md)은 2026-10-18 승인됐다. Issue #69의 구체적 규칙·표시 문구는 [제목 규칙 기준선](news-understanding-rules.md)을 따르며 실제 뉴스 품질 평가는 후속 이슈다.
2. 추가 내용이 필요하면 접근·보관·재사용 조건과 외부 전송 허용 범위를 출처별로 검토하고 별도 승인받는다. RSS 최소 보관 승인은 본문 수집·발췌 저장 승인이 아니며 이 작업은 권리 판단을 새로 수행하지 않는다.
3. [ADR 0007](../decisions/0007-news-understanding-execution-storage.md)의 네트워크 없는 규칙 기준선·SQLite 저장/재실행 계약을 따른다. 모델 선정·외부 전송·유료 호출에는 별도 결정과 명시적 승인이 필요하다.
4. 승인된 계약으로 작은 구현·표본 평가 이슈를 진행한다. 의미 통합·자동화·블로그·개인 영향 판단은 이 계약 범위 밖이다.
