# Phase 2: Tech Stack Selection

- **Status:** Draft
- **Applies to:** Phase 2
- **Purpose:** 뉴스 수집 MVP에 적합한 기술 스택을 비교하고 근거와 함께 확정한다.
- **Read when:** 1단계가 완료되어 기술 선택을 준비하거나 검토할 때
- **Related documents:** [문서 인덱스](../INDEX.md), [제품 로드맵](../product/roadmap.md), [결정 기록 안내](../decisions/README.md), [3단계 문서](03-news-collection.md)

## Goal

장기적인 가능성만 보고 복잡한 구조를 선택하지 않으면서, 3단계 뉴스 수집기를 안정적으로 개발하고 확장할 수 있는 최소 기술 기반을 결정한다.

## Prerequisites

- 1단계 문서 골격이 검토되었다.
- 3단계의 목표, 범위와 운영 기대 수준을 이해했다.
- 개인 프로젝트로서 감당할 수 있는 개발 시간과 운영 비용을 확인했다.

## Decision Areas

- 주 개발 언어와 런타임
- 첫 실행 형태: CLI, 배치, API 또는 웹 애플리케이션
- 초기 저장 방식: 파일, 내장 데이터베이스 또는 외부 데이터베이스
- 수집 인터페이스: RSS·Atom, 공식 API와 HTML 접근의 역할
- 자동 실행과 배포 환경
- 의존성, 설정과 비밀 값 관리 방식
- 테스트, 포매팅, 린트와 타입 검사 도구
- 관측 가능성과 오류 확인의 최소 수준

## Evaluation Criteria

- 첫 번째 유용한 결과까지 걸리는 시간
- 개인이 유지·운영할 때의 복잡도와 비용
- 수집, 파싱과 데이터 처리 생태계의 성숙도
- 자동 테스트와 문제 재현의 용이성
- 새 출처와 후속 분석 단계로 확장하기 쉬운 정도
- 사용자의 기존 경험과 학습 목표에 주는 가치
- 특정 공급자에 대한 불필요한 종속 위험

## Process

1. 결정에 필요한 사용자 제약과 우선순위를 확인한다.
2. 각 결정 영역에서 현실적인 소수의 선택지를 비교한다.
3. 문서 조사로 판별할 수 없는 위험만 최소 실험 대상으로 제안한다.
4. 선택과 기각한 대안, 장단점을 결정 기록에 남긴다.
5. 확정된 선택을 하나의 기술 스택 문서로 연결한다.

사용자 승인 없이 기능 구현이나 장기 운영 인프라 구축을 시작하지 않는다. 타당성 실험이 필요하면 목적과 폐기 기준을 먼저 합의한다.

## Deliverables

- `docs/architecture/tech-stack.md`
- 필요한 `docs/decisions/NNNN-*.md` 결정 기록
- 초기 디렉터리 구조와 프로젝트 초기화 계획
- 설치, 실행, 테스트와 검증 명령 계획
- 3단계 구현 전에 해결해야 할 기술 위험 목록

위 경로는 산출물이 실제로 생길 때 생성하고 [문서 인덱스](../INDEX.md)에 연결한다.

## Non-Goals

- 완성된 뉴스 수집기 구현
- 모든 후속 단계에 최적인 범용 플랫폼 설계
- 근거 없는 마이크로서비스 또는 분산 시스템 도입
- 복잡한 웹 UI와 다중 사용자 기능 결정

## Exit Criteria

- 주요 결정 영역에 확정된 선택과 근거가 있다.
- 선택하지 않은 주요 대안과 기각 이유가 기록되어 있다.
- 예상 개발·운영 비용이 개인 프로젝트 범위에서 감당 가능하다.
- 3단계를 시작할 디렉터리 구조와 검증 방법이 정해져 있다.
- 사용자 검토 후 3단계 전환 여부가 결정되었다.
