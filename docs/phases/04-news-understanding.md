- **Status:** Active

## 활성화 근거와 목표

사용자가 2026-10-15에 ADR 0004, 품질·운영·종합 검토의 한계, 3단계 완료 및 4단계 전환을 명시적으로 승인했다. Issue #61에서 그 결정을 기록한다. 단계 활성화는 아래 세부 설계 제안·모델 선정·유료 호출·외부 서비스 전송의 포괄적 승인이 아니다.

원문 근거를 잃지 않으면서 뉴스의 내용을 이해하고 기술 소식을 구분할 수 있는 작은 처리·평가 경로를 만든다. 개인 프로젝트 영향·수익성 추천은 후속 단계다.

## 첫 범위 제안

아래 내용은 **검토할 제안**이며 아직 확정된 입력·출력·저장 계약이 아니다.

1. 이미 저장된 소량 뉴스 표본을 대상으로 요약·분류에 필요한 입력을 먼저 검토한다. 표본 수·선정 기준은 후속 설계 이슈에서 합의한다.
2. 제목·URL·출처·발표 시각만으로 가능한 판단과 불가능한 판단을 구분한다. URL은 근거 위치이지 원문 내용을 읽었다는 증거가 아니다. 제목 재서술을 원문 요약으로 표시하지 않는다.
3. 내용이 부족하면 요약 보류 또는 정보 부족을 표시하는 방식을 설계한다. 추가 본문·발췌가 필요하면 출처 접근·보관·외부 전송 정책과 사용자 승인을 별도로 검토하며, 기존 RSS 승인을 본문 수집 승인으로 확대하지 않는다.
4. 생성 요약·분류는 원본 필드를 덮어쓰지 않고 원본 항목과 연결하는 방향을 검토한다. 입력 범위·근거·처리 방법을 추적할 최소 계약은 후속 설계에서 정한다.
5. 기술 발표·활용 사례·비기술 소식 등을 구분할 소수 범주와 판단 불가 처리를 제안한다. 최종 분류 체계·신뢰도 표시는 미결정이다.

## 평가 기준 제안

- 제공된 입력에 없는 사실·도입 효과·수익성을 만들어내지 않는가?
- 핵심 정보와 불확실성이 구분되고 연결된 원본을 확인할 수 있는가?
- 비기술 소식이나 애매한 항목을 기술 발표로 단정하지 않는가?
- 사용자에게 제목 목록만 보는 것보다 이해·선별에 도움이 되는가?

평가 표본·정답 작성·통과 기준은 사용자와 별도 합의한다. 자동 점수나 품질 합격을 지금 확정하지 않는다.

## 예상 산출물과 완료 조건

단계 전체의 산출물·완료 조건도 초기 제안이며 상세 이슈에서 구체화한다.

- 승인된 입력·생성 정보·근거 연결 및 저장 계약
- 작은 요약·분류 처리 경로와 외부 호출 없는 핵심 검증
- 표본 결과, 실패·정보 부족 사례와 사용자 품질 검토
- 이후 의미 기반 통합을 적용할 사건·항목 경계와 검증 근거

첫 설계 이슈의 완료 조건은 입력 충분성 판단, 최소 출력·평가 기준 제안, 미결정 사항 및 승인 순서가 명확해지는 것이다. 모델 없이 입력·출력 계약부터 검토할 수 있다. 구현·평가와 의미 통합은 별도 이슈로 나누며 모든 기능을 첫 이슈에 묶지 않는다. 사용자 명시적 결정 없이 다음 단계로 전환하지 않는다.

## 미결정 사항과 다음 이슈 순서

1. **입력·평가 설계:** 표본·내용 충분성·원문과 제목 수준 처리 구분·부족 시 처리·평가 기준.
2. **기술·저장 결정:** 로컬/외부 모델·의존성·비용 상한·개인정보와 외부 전송·생성 결과 저장·재실행 계약. 중요한 선택은 ADR로 제안한다.
3. **최소 구현·표본 평가:** 승인된 계약 아래 작은 수동 처리 경로를 구현·검증한다. 유료 호출은 별도 명시적 승인 뒤에만 수행한다.
4. **의미 통합:** 필요성이 확인되면 별도 이슈로 사건 연결 기준·오탐·검토 절차를 설계한다.

## 현재 제외 범위

이번 단계 전환 작업에는 코드 구현·모델 확정·API 호출·추가 수집·운영 DB 변경을 포함하지 않는다. 자동화·무인 실행은 별도 정책·운영 결정 대상이다. Obsidian/Quartz 글 작성·경로 복사는 선택적 확장으로 보류하고 현재 연동 문서를 만들지 않는다. 개인 영향·학습 우선순위·수익화 평가도 아직 활성화하지 않는다.
